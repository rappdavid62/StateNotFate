# Five-Year Architecture One-Pager

State Not Fate should stay simple: stabilize the person first, then expand the system only after the floor is reliable.

## Mission

Build a restartable operating system that turns state information into small visible action, preserves self-trust, and avoids shame-based streak mechanics.

## Product layers

1. Public trust surface
   - Clear explanation.
   - Evidence page.
   - Contact/join path.
   - Support boundaries.

2. Local app
   - Offline-first dashboard.
   - PIN-gated local state.
   - MVD and anchor tracking.
   - Progress history.
   - Exportable progress brief.

3. Knowledge system
   - Obsidian source map.
   - Evidence JSON.
   - Implementation notes.
   - Weekly review artifacts.

4. Automation spine
   - Hourly production monitor.
   - Weekly evidence refresh.
   - Weekly boundary audit.
   - Reviewable pull requests.

## Sequencing

### Year 1: defend the floor

- Make the public site reliable.
- Fix deploy and monitor failures.
- Make the app usable offline.
- Keep private state local.
- Convert stub docs into testable specs.

### Year 2: improve personalization

- Add better intake routing.
- Add translation drafts with human review.
- Add exportable progress briefs.
- Add synthetic test personas and edge cases.

### Year 3: build collaborator workflows

- Create review packets.
- Create manual outreach templates.
- Add consent-first sharing flows.
- Keep auto-send disabled by default.

### Year 4: research and validation

- Maintain evidence watch.
- Track usability outcomes only through allowed data.
- Prepare a clear limitations page.

### Year 5: platform decision

- Decide whether the project remains a static local-first app or needs a governed backend.
- Do not add accounts, cloud storage, or messaging until consent and logging are solved.

## Non-negotiables

- State is data, not identity.
- Restart beats streak purity.
- The floor counts.
- No autonomous sharing.
- No overclaiming.
- Boring reliability beats flashy agents.
