# Anchor Library v2

Purpose: give the user a tiny reliable action when motivation, mood, or executive function is unreliable.

## Rules

- Anchors must be concrete, visible, and finishable.
- No anchor should depend on feeling better first.
- Collapse-day anchors count. The floor is part of the system, not a failure mode.
- Prefer restart speed over streak purity.

## Anchor tiers

### Collapse floor

Use when the person is flooded, exhausted, ashamed, or unable to plan.

- Drink water.
- Sit upright for 30 seconds.
- Open the app and pick the current state.
- Put one item where it belongs.
- Send one safe contact message if isolation is making the state worse.

### Low-energy floor

Use when basic action is possible but momentum is weak.

- Ten-second start rule.
- One hygiene action.
- One food or hydration action.
- One environment reset action.
- One written proof line: what happened, what was done, what changed.

### Normal day anchors

Use when the system can tolerate more structure.

- Morning light or wake cue.
- Minimum Viable Day checklist.
- One planned task entry.
- One recovery review.
- One future-facing action.

### Good-day guardrails

Use when energy spikes and overreach risk is high.

- Cap the task list.
- Stop before collapse.
- Log the win without adding five more obligations.
- Preserve tomorrow's floor.

## Testable acceptance criteria

- Every anchor has a name, trigger, exact action, expected time cost, and fallback.
- The app must never punish a missed anchor.
- The app must make the next restart easier, not more embarrassing.
